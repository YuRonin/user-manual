# NeoAgent 建模与历史产物基准（2026-10-04）

## 任务发现

`manual discover-tasks <page-id> --json` 现在返回页面指南的步骤目标、页面状态断言、同入口已有任务的前提，以及同入口任务列表。四类信息只作为待审阅候选；`verified: false` 不会变成任务审批或浏览器执行权限。

候选输入可用 `guideStep` 引用页面指南，明确写出 `action.type` 后由 CLI 填入步骤 ID、说明、页面、目标。一个匹配步骤从这五处信息加动作类型，缩为指南 ID 加动作类型两处输入；缺失指南或动作类型会整批拒绝。fixture 实测保存状态仍为 `candidate/pending`。这是**字段输入减少**，并非真实人员建模耗时测量。

对现有三个任务按任务 YAML 与入口页面模型做精确匹配。`步骤目标`只计与指南目标完全一致的步骤；`完成断言`只计声明引用的页面断言。匹配的三个步骤若在首次建模时用简写，共可少填 9 处步骤字段。此表是现有任务的回算，不代表三篇既有任务当初减少了多少人工时间。

| 任务 | 步骤目标可复用 / 全部步骤 | 完成断言可复用 / 全部声明 | 首次建模仍须人工判断 |
| --- | ---: | ---: | --- |
| use-skill | 1 / 6 | 1 / 1 | 技能选择、搜索、发送后的实际结果、异常分支 |
| review-credits | 0 / 3 | 0 / 1 | 导航位置、额度数值、完成判断 |
| generate-practice | 2 / 4 | 1 / 1 | 预填内容、提交授权、题目预览与内容核对 |

同入口的既有任务可再提供前提：这三个任务当前分别能复用 2、1、2 条，但这是**已有任务之后**的复用，不计作首次建模节省。新建任务仍需人工填目标、风险、其余步骤和前提，并逐条核对候选。下一轮应记录新任务从空白到审批的真实编辑次数与用时，才可声称总手填量下降。

## 历史产物

运行 `manual gc --inventory --json` 获得逐项路径、大小、保留原因和盘点 hash；它只读。2026-10-04 的 NeoAgent 盘点：

| 类别 | 数量 | 字节 | 当前保留依据 |
| --- | ---: | ---: | --- |
| 发布记录 | 45 | 684,389 | 6 个当前发布；39 个历史发布用于版本恢复 |
| 模型快照 | 83 | 22,608,839 | 1 个当前模型；82 个构成完整父链 |
| Capture 记录 | 49 | 281,542 | 38 个仍被引用；11 个按未引用保留期处理 |
| 发布图 | 42 | 17,549,266 | 35 个被引用；7 个按未引用保留期处理 |

盘点 hash：`sha256:3010eb41b73ae0af8753c18f7ff6c1de59db6b7480febd50e25e01af2136b94c`。发布图的“未引用”只表示当前引用图没有指向它；清理还须遵循现有 `gc` 的时间门槛。当天 `manual gc --json` 的可回收对象为 0，故没有执行删除。

若发布记录、Capture 记录、当前模型损坏，或页面 / 任务工作副本尚未提交，`gc` 现在拒绝生成和应用回收计划，返回 `retention-reference-unavailable`；不能把“读不出引用”当成“没有引用”。只读盘点会返回 `referenceErrors` 供修复。

当前 82 个旧模型快照全部位于当前快照的父链。若要回收这 22 MB，先需明确历史恢复窗口并实现可验证的链截断或压缩；直接删旧快照会破坏现有恢复链。历史发布同理，要先定义保留版本数、固定版本和恢复演练，再提供显式应用及计划 hash 复核。现阶段重复内容的发布已复用当前 release，阻止继续增加同内容记录。
