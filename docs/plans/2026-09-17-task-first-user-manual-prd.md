# Task-first Living User Manual PRD

> 日期：2026-09-17  
> 状态：已完成产品讨论，待进入实现规划  
> 目标版本：Living User Manual 下一阶段 MVP  
> 首批验收项目：NeoAgent 个人中心

## 1. 背景

当前 MVP 以“页面”为最小单位：`inspect` 建立页面模型，`describe` 补充页面标题、用途和 `detectedActions`，`capture` 截取页面初始状态，`generate` 将这些事实拼成一篇页面说明。

这一模式可以回答“产品有哪些页面”，但不能可靠回答“用户怎样完成一件事”。在 NeoAgent 个人中心试运行中暴露出以下问题：

1. 页面模型缺少用户任务、前置条件、完成标志、条件分支和风险等级。
2. `capture` 只会打开页面并截取初始状态，不能点击入口、展开抽屉或记录交互后的页面状态。
3. 配置预留了标注图目录，但尚无实际的标注能力与视觉规范。
4. 原始截图直接位于文档发布目录，可能包含昵称、学校、积分和历史会话等真实信息。
5. `generate` 只是把 `detectedActions` 展开为有序列表；输入事实过薄，润色无法把它变成可执行指南。
6. 当前 `verified` 只代表页面成功打开并完成截图，不代表每项操作和结果都被浏览器验证。
7. 事实校验要求操作列表数量保持不变，会把粗粒度动作永久锁定为粗粒度文档。

例如当前“个人中心”文档只列出“编辑资料”“继续完善”“查看信息”和“打开服务”等并列动作，但没有说明如何打开资料抽屉、哪些字段可修改、冷却期会造成什么限制、如何判断任务完成，也没有展示“学校权益”抽屉等交互状态。

## 2. 产品决策

手册采用双层结构：

- **页面模型**负责页面位置、可见元素、可达状态及源码证据。
- **用户任务模型**负责用户目标、前置条件、操作步骤、风险、分支、完成标志和配套截图。

最终发布内容以用户任务为主体，例如“修改个人资料”“查看学校权益”；页面文档只作为能力总览和任务入口。

任务采用“自动发现 + 人工确认”的混合方式。系统根据源码、运行页面和产品导航提出候选任务，用户确认、合并、删除、改名和排序后，任务才可进入截图和生成阶段。

## 3. 目标

### 3.1 用户目标

1. 用户能够按真实目标查找指南，而不是先猜功能属于哪个页面。
2. 用户能够根据步骤和截图完成任务，并知道何时算完成。
3. 用户可以看到抽屉、弹窗、菜单等必须交互后才出现的界面状态。
4. 用户不会在公开手册中看到真实账号的敏感信息。

### 3.2 产品目标

1. 建立独立、可复用、可跨页面的用户任务模型。
2. 让浏览器按照安全边界执行任务步骤并采集关键状态。
3. 提供可配置、有一致视觉语言的截图标注系统。
4. 将确定性事实、AI 编辑和程序校验继续分层，提升内容质量但不牺牲可信度。
5. 为页面或源码变化影响哪些任务提供可追踪索引。

### 3.3 MVP 成功标准

在 NeoAgent 个人中心完整跑通以下两个任务：

- 修改个人资料。
- 查看学校权益。

每个任务都必须从候选发现开始，经过人工确认、安全交互、关键状态截图、脱敏、标注、任务指南生成和发布校验。

## 4. 非目标

MVP 不包含：

- 自动执行保存、删除、支付、权益切换等真实写操作。
- 自动构造或恢复数据库 Fixture。
- 穷举所有加载、空状态、接口异常和罕见业务分支。
- 视频、GIF、鼠标轨迹动画或录屏式教程。
- 移动端截图与响应式手册。
- 多语言手册。
- 使用用户行为数据自动决定任务优先级。
- 无人工确认的全自动批量发布。
- 通用 OCR 级图片脱敏。
- 将每个按钮或链接机械地转换为独立任务。

数据结构需要从一开始支持跨页面任务，但跨页面任务不作为首版验收阻塞项。

## 5. 核心原则

### 5.1 任务优先

发布单元是用户任务，不是页面。页面是任务执行所需的上下文与证据来源。

### 5.2 证据优先

文档中的 UI 名称、截图、页面状态、业务限制和完成结果必须有源码、浏览器或人工确认依据。

### 5.3 人工确认任务边界

AI 可以提出候选任务，但不能绕过人工确认直接发布。人工确认解决任务粒度、业务优先级和跨页面语义问题。

### 5.4 安全执行

浏览器自动执行只读和可恢复的本地操作。写入和破坏性操作默认停在提交前。

### 5.5 隐私默认保护

原图默认不进入发布目录。脱敏检查未通过时，不生成正式图片和正式文档。

### 5.6 原子发布

一篇任务 Markdown 及其引用的全部图片必须同时成功后才能替换旧版本，避免出现半成品。

## 6. 信息架构

建议发布目录：

```text
docs/manual/
├─ index.md
├─ pages/
│  └─ user-center.md
├─ tasks/
│  ├─ edit-profile.md
│  └─ view-school-benefits.md
└─ images/
   └─ annotated/
      ├─ edit-profile--entry.png
      ├─ edit-profile--editor-open.png
      └─ view-school-benefits--sheet-open.png
```

- `index.md`：按用户目标或产品区域组织的总目录。
- `pages/*.md`：页面用途、可完成的任务以及相关入口，不再承担完整教程。
- `tasks/*.md`：正式的任务型使用指南。
- `images/annotated/*`：唯一允许正式文档引用的发布图片。

建议项目状态目录：

```text
.manual/
├─ config.yaml
├─ project.yaml
├─ pages/
├─ tasks/
├─ index/
├─ drafts/
└─ artifacts/
   ├─ raw/
   ├─ sanitized/
   ├─ diagnostics/
   └─ manifests/
```

`artifacts/` 默认加入 `.gitignore`。原图和诊断图不得进入正式文档目录。

## 7. 用户任务模型

### 7.1 示例

```yaml
id: edit-profile
title: 修改个人资料
goal: 更新昵称、性别或教学信息
entryPage: user-center
priority: high
preconditions:
  - 已登录
risk: local
status: approved

steps:
  - id: open-editor
    instruction: 点击「编辑资料」
    page: user-center
    stateBefore: default
    stateAfter: edit-profile-open
    action:
      type: click
      target:
        role: button
        name: 编辑资料
    capture:
      timing: before
      annotations:
        - target: action.target
          label: 1

  - id: review-fields
    instruction: 修改需要更新的资料
    page: user-center
    stateBefore: edit-profile-open
    stateAfter: edit-profile-open
    action:
      type: inspect
    capture:
      timing: after
      focus: dialog
      annotations:
        - target:
            label: 昵称
          label: 2
        - target:
            label: 学科
          label: 3

  - id: save-profile
    instruction: 确认资料无误后，点击「保存修改」
    page: user-center
    stateBefore: edit-profile-open
    action:
      type: click
      target:
        role: button
        name: 保存修改
    risk: write
    execution: stop-before-action

completion:
  description: 资料编辑面板关闭，个人中心显示更新后的内容
  verification: expected

branches:
  - id: teaching-info-cooldown
    condition: 教学信息处于冷却期
    effect: 学科和年级不可修改

relatedTasks:
  - adjust-ai-preferences
  - view-school-benefits
```

### 7.2 必填字段

每个正式任务至少包含：

- 稳定 `id`。
- 面向用户目标的 `title`。
- 明确的 `goal`。
- 入口页面 `entryPage`。
- `preconditions`。
- 任务级默认 `risk`。
- 至少一个有稳定 `step.id` 的步骤。
- `completion`。
- 生命周期 `status`。

### 7.3 生命周期

```text
candidate → approved → captured → generated → verified
```

- `candidate`：系统提出，尚未人工确认。
- `approved`：任务边界、标题和目标已人工确认。
- `captured`：全部必需截图步骤已获得合格证据。
- `generated`：已生成通过事实校验的正式文档。
- `verified`：文档、图片、脱敏和引用均通过最终校验。

任一步失败不得跳过状态。源码或相关页面变化后，受影响任务进入 `stale`，保留原产物但不得声称仍为最新。

## 8. 页面状态模型

页面状态描述用户可见的稳定状态，不记录所有前端内部状态。

```yaml
page: user-center
states:
  default:
    description: 个人中心初始状态
  edit-profile-open:
    description: 编辑资料抽屉已打开
  school-benefit-open:
    description: 学校权益抽屉已打开
```

要求：

1. 状态名称在页面范围内稳定。
2. 状态必须有可验证的可见条件，例如标题、dialog、按钮或 URL。
3. 多个任务可以复用同一页面状态和截图证据。
4. 当前 `browser.screenshot` 继续兼容为 `default` 状态的旧式页面截图，迁移期内不得破坏现有项目。

## 9. 截图证据模型

每个截图产物必须有证据清单：

```yaml
task: edit-profile
step: review-fields
page: user-center
pageState: edit-profile-open
url: /user-center
capturedAt: 2026-09-17T10:00:00Z
viewport: 1440x900
deviceScaleFactor: 2
raw: .manual/artifacts/raw/edit-profile--review-fields.png
sanitized: .manual/artifacts/sanitized/edit-profile--review-fields.png
annotated: docs/manual/images/annotated/edit-profile--review-fields.png
targets:
  - label: 2
    role: textbox
    accessibleName: 昵称
    rect: { x: 0, y: 0, width: 0, height: 0 }
redactions:
  - kind: phone
    rect: { x: 0, y: 0, width: 0, height: 0 }
```

证据清单不得保存识别出的手机号、邮箱、姓名等敏感原文，只保存类型、位置和处理结果。

## 10. 任务发现与人工确认

### 10.1 发现来源

候选任务同时使用：

1. 源码语义：按钮、表单、弹窗、跳转、条件渲染和业务规则。
2. 浏览器运行态：实际可见元素、可访问名称和当前账号可进入的状态。
3. 产品结构：导航入口、页面之间的关系和现有页面索引。

### 10.2 候选任务筛选

优先保留满足以下条件的目标：

- 有明确完成结果。
- 需要两个或以上动作，或者入口不明显。
- 用户可能不知道如何开始或如何判断成功。
- 存在权限、条件限制或阻断分支。
- 对产品核心价值有明显贡献。

单纯导航、重复入口和无独立结果的按钮不应机械地生成任务。

### 10.3 候选任务展示

每个候选任务至少展示：

- 任务名称。
- 用户目标。
- 入口页面。
- 预计步骤数。
- 风险等级。
- 来源证据摘要。
- 系统的保留、合并或舍弃建议。

### 10.4 人工确认能力

用户可以：

- 接受或拒绝候选任务。
- 合并重复任务。
- 修改标题和用户目标。
- 调整优先级。
- 指定暂不覆盖的分支。
- 补充源码无法发现的业务任务。

确认过程优先在 Skill 对话中完成，确定性程序负责验证输入并写入 `.manual/tasks/`。用户不需要直接编辑 YAML。

## 11. 命令与工作流

目标工作流：

```text
manual inspect
  → manual discover-tasks <page-id|--all>
  → 人工确认
  → manual plan-capture <task-id>
  → manual capture-task <task-id>
  → manual generate-task <task-id>
  → manual verify <task-id>
```

命令名称可在实现计划阶段校正，但产品能力和阶段边界必须保持：

1. 页面发现与任务发现分离。
2. 未批准任务不能截图和发布。
3. 截图计划先于浏览器执行生成，用户能够看到将执行哪些操作。
4. 任务截图与页面静态截图并存，旧命令保持兼容。
5. 生成与验证分离，验证失败不得覆盖正式文档。

## 12. 浏览器执行与安全边界

### 12.1 执行流程

```text
恢复登录会话
→ 打开任务入口
→ 解析语义目标
→ 执行允许的交互
→ 断言目标状态
→ 截取原图
→ 脱敏
→ 裁剪与标注
→ 写入证据清单
→ 清理输入并关闭隔离会话
```

### 12.2 元素定位优先级

1. ARIA role + accessible name。
2. 表单 label。
3. 可见文字。
4. 稳定的 `data-testid`。
5. 人工补充的 CSS selector。

AI 负责描述语义目标，程序负责解析元素与计算位置。AI 不直接写像素坐标。

如果目标不存在、不可见或匹配到多个元素，执行器必须停止，不能随机选择。

### 12.3 风险等级

| 等级 | 示例 | 默认行为 |
|---|---|---|
| `read` | 导航、展开抽屉、打开菜单、切换 Tab | 自动执行 |
| `local` | 输入但不提交、调整未保存的本地控件 | 使用示例数据执行，结束后清理 |
| `write` | 保存资料、提交表单、切换权益 | 停在动作前，不执行 |
| `destructive` | 删除、支付、不可逆发布 | 不执行，只记录入口和风险 |

只有任务明确配置测试环境、测试数据、允许的写操作和恢复动作时，才允许验证 `write`。

### 12.4 状态验证

每个交互步骤需要描述预期状态，例如：

- 指定 dialog 或 sheet 出现。
- 指定标题可见。
- URL 发生预期变化。
- 某个字段进入可编辑状态。

仅完成点击但未满足状态断言，不算步骤成功。

## 13. 截图策略

采用“关键状态截图”，不要求每一步都产生图片。

- 任务入口：整页截图并标出入口。
- 抽屉、弹窗、菜单或复杂表单打开后：截取交互后的稳定状态。
- 提交前：在必要时标出关键字段和提交按钮。
- 无明显状态变化的简单导航不重复截图。
- 同一张图最多标注 3–5 个目标。
- 图片编号必须与正文步骤一一对应。

局部裁剪必须保留位置锚点，例如页面标题、弹窗标题或邻近导航，避免读者失去上下文。

## 14. 标注视觉系统

### 14.1 主题机制

标注样式必须通过 `annotationTheme` 配置。系统内置 `default` 主题，项目可以覆盖字段或新增主题。

示例配置：

```yaml
annotation:
  activeTheme: default
  themes:
    default:
      primary: "#E86349"
      primaryDark: "#B84331"
      halo: "rgba(232, 99, 73, 0.16)"
      labelBackground: "rgba(255, 255, 255, 0.96)"
      labelText: "#252C38"
      focusMask: "rgba(33, 50, 113, 0.10)"
      fallbackColor: "#213271"
      markerSize: 30
      outlineWidth: 3
      targetPadding: 5
      targetRadius: 8
      maxMarkersPerImage: 5
```

所有新增字段均为可选字段；旧配置缺失时自动补充 `default`，不提升配置结构版本。

### 14.2 `default` 视觉语言

`default` 是“编辑型指南标注”风格：使用珊瑚橙说明层、暖白文字标签和轻度深蓝聚焦遮罩，与冷白、海军蓝为主的业务 UI 清晰分层。

#### 编号标记

- 28–32 px 圆形徽标。
- 珊瑚橙背景、白色数字、2 px 白色外环。
- 默认放在目标左上角外侧，不遮挡按钮或字段文字。
- 无法邻接时使用短引导线。

#### 高亮框

- 3 px 主色描边。
- 常规控件 8 px 圆角，大型卡片可用 12 px。
- 与目标保持 4–6 px 间距。
- 使用轻量光晕，不使用厚重阴影。
- 操作目标使用实线框，仅查看区域使用虚线框。

#### 文字标签

- 字体采用 Noto Sans SC、微软雅黑等中文无衬线字体。
- 字号 14–16 px，最多两行。
- 暖白背景、珊瑚橙细边框、8 px 圆角。
- 标签说明“做什么”，不机械重复页面上已有的按钮文字。
- 无法避让业务内容时放入截图外侧说明栏。

#### 聚焦

- 整页入口图保持页面原亮度，只标入口。
- 抽屉或弹窗图可对非焦点区域添加约 10% 深蓝遮罩。
- 不使用放大镜、手绘箭头、荧光笔或测试报告式纯红框。

### 14.3 可访问性与自动适配

- 顺序不能只靠颜色表达，必须同时显示数字。
- 标签文字对比度至少达到 WCAG AA。
- 自动检测标注是否遮挡按钮名、字段值或关键反馈。
- 当珊瑚色与目标背景对比不足时，切换到 `fallbackColor`。
- 标注布局需要适配不同 DPR 和裁剪区域。

## 15. 隐私与脱敏

### 15.1 产物分层

```text
.manual/artifacts/raw/          原图，不提交
.manual/artifacts/sanitized/    脱敏中间图，不提交
docs/manual/images/annotated/   可发布标注图
```

正式 Markdown 只能引用 `annotated` 目录中的图片。

### 15.2 MVP 检测方式

MVP 使用以下信息组合定位敏感内容：

- DOM 元素边界与可访问语义。
- 手机号、邮箱、账号标识等文本规则。
- 字段名称、输入类型和常见敏感属性。
- 任务或项目配置中的显式 `redact` 与 `preserve` 规则。
- 页面运行时已知的当前账号数据。

姓名、学校、会话标题等难以只靠正则判断的内容优先由页面语义和显式规则处理。无法可靠判断时必须阻止发布并请求人工确认。

### 15.3 处理方式

- 优先使用稳定示例值替换或不透明遮盖。
- 不使用仍可能辨认原文的模糊滤镜作为唯一处理。
- 证据清单只记录敏感类型、区域和处理结果。
- 脱敏在标注之前完成，避免标注位置泄露原始内容。

## 16. 任务指南生成

### 16.1 内容结构

正式任务指南默认包含：

1. 一级标题：用户目标。
2. 目标说明：完成后会得到什么。
3. “开始前”：登录、权限、账号状态等前置条件。
4. “操作步骤”：明确动作、目标和状态变化，配关键截图。
5. “完成标志”：用户如何判断任务完成。
6. “条件分支”：只包含阻断主流程的重要差异。
7. “相关任务”：引导到相邻目标。

MVP 只覆盖主流程和阻断性分支，不把所有异常状态写入正式指南。

### 16.2 生成流水线

```text
已批准任务
+ 页面状态
+ 浏览器步骤证据
+ 截图清单
+ 源码业务限制
        ↓
确定性任务草稿
        ↓
AI 中文编辑
        ↓
结构与事实校验
        ↓
正式任务指南
```

### 16.3 事实保护

生成器必须保护：

- `step.id` 与步骤顺序。
- 已确认的 UI 原文。
- 步骤与截图、页面状态的映射。
- 前置条件、风险等级和阻断分支。
- 已验证行为与预期行为的区别。
- 路由、数字、额度、权限和业务规则。

未执行写操作时，生成器不能声称已经通过浏览器验证保存结果。完成标志必须标记为 `verified` 或 `expected`。

不再以“润色前后有序列表条数完全一致”作为唯一保护方式；校验应基于结构化任务事实。

### 16.4 内容质量门禁

正式指南必须满足：

- 标题表达用户目标，而不是页面名称。
- 有明确前置条件和完成标志。
- 每一步都有动作、目标和预期状态。
- 关键交互状态有截图证据。
- 图片编号与步骤一致。
- 不出现“点击相关按钮”“进行设置”等模糊指令。
- 不把导航入口和真正任务混成并列功能清单。
- 不新增没有证据的时间、额度、权限或结果。
- 写操作未执行时准确表达验证边界。

## 17. 失败处理

| 失败 | 行为 |
|---|---|
| 候选任务证据不足 | 保留为 `candidate`，不能自动批准 |
| 元素不存在或不可见 | 停止当前步骤，输出目标与页面状态 |
| 元素匹配多个 | 停止，不随机选择 |
| 状态断言失败 | 保存诊断图，不进入手册 |
| 遇到未授权写操作 | 停在操作前，标记 `not-executed` |
| 脱敏置信度不足 | 阻止图片和文档发布 |
| 标注遮挡关键内容 | 自动重新布局，仍失败则请求人工调整 |
| 生成事实冲突 | 保留草稿，不覆盖正式文档 |
| 单个任务失败 | 不阻塞其他任务，该任务保持非完成状态 |

错误信息必须包含任务、步骤、页面状态、目标元素、失败分类和可执行的修复建议。

## 18. 索引与增量更新

现有页面正逆索引需要扩展任务关系：

```text
源码文件 → 页面 → 页面状态 → 任务步骤 → 任务文档与截图
```

至少支持查询：

- 某页面承载哪些任务。
- 某任务依赖哪些页面和源码文件。
- 某源码文件变化会使哪些任务过期。
- 某截图被哪些任务文档引用。

入口文件、相关组件、UI 名称或任务依赖状态变化时，任务应进入 `stale`。仅文案样式变化不应无条件使所有截图过期。

## 19. 兼容与迁移

1. 现有 `manual inspect`、`describe`、页面 `capture` 和页面 `generate` 在迁移期保持可用。
2. 旧页面的 `detectedActions` 可以作为候选任务发现的输入，但不能直接视为正式任务。
3. 旧 `browser.screenshot` 视为页面 `default` 状态的静态证据。
4. 新增配置字段必须提供默认值，不因为新增主题配置提升 `config.version`。
5. 新任务产物使用新的目录，不覆盖旧页面文档，直到项目显式启用 task-first 输出。
6. 原始截图迁出发布目录需要提供迁移检查，不能静默删除用户已有文件。

## 20. 测试要求

### 20.1 单元测试

- 任务模型解析、校验和生命周期。
- 风险继承与步骤级覆盖。
- 页面状态与状态断言。
- 主题默认值、覆盖和非法配置。
- 任务事实提取与生成校验。
- 产物路径和原子发布。

### 20.2 浏览器夹具测试

- 弹窗、抽屉、下拉框、Tab 和表单输入。
- 条件渲染与不可见目标。
- 同名按钮导致的歧义。
- 状态断言成功和失败。
- `read`、`local`、`write`、`destructive` 四类风险。

### 20.3 标注测试

- 页面边缘目标与密集目标。
- 不同 viewport 和 DPR。
- 裁剪后的坐标变换。
- 标签自动避让。
- 主题覆盖与备用颜色。
- 最大标注数量门禁。
- 黄金图回归，防止视觉样式意外漂移。

### 20.4 脱敏测试

- 手机号、邮箱、姓名、学校和会话标题。
- DOM 边界到图片像素的换算。
- 显式 `redact` 和 `preserve` 冲突。
- 检测不确定时阻止发布。
- 证据清单不保存敏感原文。

### 20.5 端到端测试

从页面扫描、候选任务、人工批准输入、截图计划、安全交互、脱敏标注到 Markdown 发布跑通完整链路，验证：

- 图片路径有效。
- 图中编号与步骤一致。
- 未执行写操作。
- 正式文档没有引用 raw 或 sanitized 图片。
- 任一环节失败时不产生半成品。

## 21. 首批验收任务

### 21.1 修改个人资料

必须做到：

1. 自动发现并提出任务。
2. 人工确认后写入结构化任务文件。
3. 自动打开个人中心并定位「编辑资料」。
4. 截取个人中心入口与资料抽屉两个关键状态。
5. 识别昵称、手机号、学校和历史会话等敏感内容。
6. 使用 `default` 主题生成发布图。
7. 图中编号与正文步骤一致。
8. 停在「保存修改」之前，不实际提交。
9. 说明教学信息冷却期这一阻断分支。
10. 生成包含目标、开始前、步骤、完成标志和相关任务的指南。

### 21.2 查看学校权益

必须做到：

1. 从个人中心定位「学校权益」入口。
2. 点击后断言学校权益抽屉出现。
3. 截取入口和抽屉展开状态。
4. 展示当前生效权益、可用选项和不可切换原因。
5. 不执行权益切换。
6. 对学校名称和账号相关信息执行脱敏。
7. 将“查看权益”和“切换权益”区分为只读任务与写操作边界。

## 22. MVP 验收清单

- [ ] 候选任务需要人工确认后才能继续。
- [ ] 页面模型与任务模型独立存在并互相引用。
- [ ] 一个页面可以有多个可复用状态。
- [ ] 浏览器支持安全交互和状态断言。
- [ ] 风险等级能够阻止未授权写操作。
- [ ] 原图不进入发布目录。
- [ ] 脱敏失败能够阻止发布。
- [ ] `annotation.activeTheme` 默认为 `default`。
- [ ] 主题颜色、尺寸、圆角、标注数量和备用色可配置。
- [ ] 标注图遵守编号、避让、对比度和聚焦规则。
- [ ] 任务文档按目标组织，并包含规定章节。
- [ ] 已验证行为与预期行为在数据和文案中明确区分。
- [ ] 正式文档和图片原子发布。
- [ ] 页面或源码变化可以追踪到受影响任务。
- [ ] 两个个人中心验收任务通过完整闭环。

## 23. 建议交付顺序

1. **任务基础**：任务模型、生命周期、候选发现、人工确认和任务索引。
2. **交互采集**：页面状态、截图计划、安全交互、语义定位和状态断言。
3. **发布图片**：产物分层、脱敏、裁剪、`default` 主题和标注布局。
4. **内容质量**：任务草稿、中文编辑、结构化事实校验和原子发布。
5. **实际验收**：在 NeoAgent 个人中心跑通两个首批任务。

## 24. 后续方向

MVP 验证后再评估：

- 人工浏览器演示录制，并从轨迹反推或补充任务。
