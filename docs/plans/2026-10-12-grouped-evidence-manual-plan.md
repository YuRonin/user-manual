# 使用手册改造计划：按操作类别组织图文，以浏览器证据连接说明与标注

日期：2026-10-12

状态：工具实现及回归已完成（阶段 A～D）。NeoAgent 业务验收由用户重新运行后完成（阶段 E）。

代码核对基线：user-manual `537b09f`，以及 NeoAgent 当前的登录、AI 对话手册与 Capture 记录。

## 1. 要解决的问题

用户提出了两个相互关联的问题：

1. 手册已经介绍了功能，截图却没有对应标注。例如「登录与注册」第七项学校账号登录，以及「AI 对话」中大部分操作。
2. 一张整页截图承载太多不同类别的功能，读者要在大图和长篇说明之间来回寻找。应按操作类别分别截图、标注和说明。

目标是让每个图文小节围绕读者要完成的一类操作展开，并且每项操作说明都有适当的界面证据。不能把“补 target 后重画图片”作为长期工作流，也不能通过减少说明来掩盖截图不足。

## 2. 已核实的现状与原因

### 2.1 NeoAgent 的两个实例

| 实例 | 模型与采集事实 | 原因 |
|---|---|---|
| 登录第七项「用学校账号登录」 | 源码有 `NeoStar学校管理台账号登录` 按钮和授权逻辑；截图中按钮可见；guide 没有 target；Capture 记为 `target-not-declared` | 文案和浏览器定位信息没有关联完整 |
| AI 对话的十项介绍 | 只有第 1、2、4 项有 target 并画出；另外七项全部记为 `target-not-declared` | 缺少目标被直接跳过，没有尝试将浏览器候选关联到说明 |
| AI 对话的发送、附件、历史入口 | 浏览器候选包含「发送」「添加文件附件」「查看全部对话」 | 已观察到控件，但发现结果没有进入功能关联流程 |
| AI 对话的组合技、拖拽、产物查看 | 需要菜单、拖拽提示或已有产物等状态 | 补充初始页的定位信息也不能覆盖完整说明 |

复核入口：

- NeoAgent `demo/website/.manual/pages/login.yaml`、`pages/chat.yaml`。
- 登录 Capture：`c50784e2-f2d9-435a-a540-cdd5c10ab2c6`。
- AI 对话 Capture：`9bd2316b-d32e-413f-b5b2-d1f0c1010d0f`。
- 正式文档：`demo/website/docs/manual/login.md`、`chat.md`。

这些记录证明入口或控件被观察到，不等于整个登录、生成或上传流程已经实际执行成功。

### 2.2 工具内的具体原因

- `src/annotations/coverage.js` 根据 guide 构造清单；缺少 target 的 guide 默认是 optional。程序无法区分“纯概念说明”和“有操作但遗漏定位配置”。
- `src/evidence/capture-page.js` 对缺少 target 的计划项直接记录 `target-not-declared`，不进入定位。
- DOM 候选保留为待确认清单，没有自动关联回功能和操作。
- `src/generate/render.js` 先集中展示默认图、变体图，再输出 guide 小节；图片与说明缺少直接的所属关系。
- 默认图上的编号来自 guide 的数组下标，功能介绍顺序与图片编号耦合。
- 当前覆盖检查主要围绕显式 required 功能，无法保证正式正文中每项操作都具有证据。

需要修正前面分析中的简化表述：工具不是完全没有发布门禁。`src/publication/validate.js` 对 public 正式发布会阻断未决功能；internal 主要警告。NeoAgent 配置为 `audience: internal`。AI 对话 Capture 的 `ok: true`、`complete: false`、`required.total: 0` 反映的是现有口径，不能理解为完整覆盖。

### 2.3 应复用的已有能力

当前源码已经支持页面 `variants`、Scenario setup/checkpoint、多状态证据、事实包与冻结证明、缓存、图片派生和发布事务。已有 `maxMarkersPerImage`（默认 5）及标注分图能力。

因此不能把“增加多图支持”或“降低标注上限”当作主要方案。数量拆分仍可能重复同一整页图；当前真正缺少的是语义分类、图文对应、目标关联，以及跨图片的正文证据检查。`docs/ARCHITECTURE.md` 的部分能力说明滞后于源码，实施时一并更新。

## 3. 推荐方案与设计取舍

采用一个主方案：**功能模型 + 图文小节计划 + 经验证的浏览器绑定 + 文档级覆盖检查**。

```text
源码分析与现有任务模型
        ↓
功能与操作模型 ── 浏览器观察、AI 语义消歧
        ↓                    ↓
按读者目标组织图文计划 ← 已验证的控件和状态绑定
        ↓
Scenario 回放、状态断言、稳定截图
        ↓
隐私处理、局部裁剪、选择性标注
        ↓
按小节装配图片与说明，锁定事实引用
        ↓
对正式正文重算覆盖 → 原子发布
```

类别由 AI 理解读者目的后提出；程序校验关联与执行事实。程序不根据按钮位置或关键词擅自判断业务类别，也不开放无约束的浏览器探索。

| 方案 | 结论 |
|---|---|
| 从最终文案抽取按钮名，批量补 target | 可用于旧数据迁移的线索，不能作为正式事实来源；名称、状态、步骤容易误配 |
| 降低单图标注上限，机械分页 | 只处理拥挤，无法处理类别混杂和状态缺失 |
| 用截图视觉猜按钮并直接画框 | 缺少稳定的元素与状态证据；不作为主要路径 |
| 重建一套独立任务执行引擎 | 与现有 Scenario、任务、权限及缓存逻辑重复；不采用 |
| 在现有流程中引入小节、图片、操作的显式关联 | 推荐；复用现有执行与证据模块，修改职责清楚 |

## 4. 图文组织规则

### 4.1 小节围绕读者目标

页面继续负责路由身份和入口。页面手册内部按操作类别组织小节；真正跨页面、具有完成目标的流程继续使用任务指南，可在小节中关联已有 taskId。

每个小节包含：目的、必要前提、操作说明、相邻图片、图片标注说明及必要的结果说明。不同小节引用不同的功能集合和页面状态。总览图可选，默认不承担所有操作的标注。

不要求一个类别只有一张图。入口、菜单、结果可以分别展示，避免把不同状态合并成不存在的界面。

### 4.2 每张图只表达一个状态和一组相关操作

- 默认建议 1～3 个标注，硬上限复用现有配置，默认 5。
- 先按目的与状态拆图，再检查标注数量和空间；数量超限时在同一小节内继续拆分。
- 有操作步骤的图必须有所属说明；纯总览或结果图可不带数字，但须声明用途。
- 优先围绕登录卡片、输入区、菜单、弹窗等有上下文的区域裁剪；不裁成孤立图标，不切掉理解所需的标题或关联控件。
- 可见范围、字体大小、标注碰撞和缩放后的可读性都要检查。超过上限、标注越界或被遮挡时，不得直接输出一张失败图。
- 同一初始状态可复用一次采集，再为不同类别派生不同区域和标注。分类截图强调读者看到的图文，不能为了形式重复打开浏览器。
- 同一张整页图重复多次、只替换标注，不作为默认拆图策略。无法合理裁剪时保留上下文，并说明选图理由供审阅。

### 4.3 编号与身份分离

功能、操作、小节、图片使用稳定 ID；顺序和显示编号均为派生值。

每张图的标注从 1 开始。正文引用由程序生成的图片及标注关系，例如“在下图的 ① 输入需求，点击 ② 发送”。步骤序号与标注号分开，不能继续用 guide 下标充当全篇图片标注号。调整小节顺序不得改变功能身份。

## 5. 功能模型与图文计划

### 5.1 单一语义来源

扩展现有 `page.features`，作为功能身份和范围决定的来源；新增页面内的图文小节与图片计划。旧 guide 通过兼容读取与迁移关联到功能，不长期维护两份功能介绍。

| 对象 | 责任 | 建议内容 |
|---|---|---|
| Feature | 定义一个业务功能 | id、label、sourceRefs、scopeDecision、contentKind、operations |
| Operation | 定义可描述或执行的动作 | id、actionKind、targetHint、stateRef、risk、evidenceRequirement |
| Section | 定义读者要完成的一类操作 | id、title、goal、featureRefs、说明块引用、figureRefs、taskRefs |
| Figure | 定义一张图要说明什么 | id、sectionId、scenarioId、checkpointId、feature/operationRefs、frame、captionPurpose |
| Binding | 记录实际控件关联 | featureId、operationId、候选及定位策略、状态、角色、观察来源、验证结果 |
| EvidenceLink | 连接说明与最终证据 | 小节/说明块、操作、图片、标注、Capture、来源和验证范围 |

`targetHint` 是线索，Binding 是已验证结果。已有显式 target 可作为首选线索保留；它仍必须通过浏览器确认。一个功能可以有多个动作和状态，不能继续假设“一项功能只有一个 target”。

Feature 的收录决定、定位状态和证据要求是不同维度：

- scopeDecision 沿用 required / optional / skip / undecided 的范围意义。
- contentKind 区分操作、概念和参考内容，不根据 target 是否存在推导。
- bindingStatus 区分 unresolved / ambiguous / verified / stale。
- evidenceRequirement 区分入口标注、状态截图、动作结果或明确的无图说明。

optional 表示可选择不收录。一旦该操作进入正式正文，就必须满足其证据要求；不能因缺少 target 自动转成不需要证据。

### 5.2 计划形状示例

以下是拟议语义输入示例，不是现有 CLI 已支持的字段；最终 schema 在第一阶段确定。模型提交 JSON，由程序校验后落盘，不要求 AI 手写项目 YAML。

```json
{
  "pageId": "chat",
  "sections": [
    {
      "id": "start-conversation",
      "title": "开始对话",
      "goal": "描述教学需求并开始一轮对话",
      "featureRefs": ["page:chat:new-conversation", "page:chat:send"],
      "figureRefs": ["chat-input"]
    }
  ],
  "figures": [
    {
      "id": "chat-input",
      "sectionId": "start-conversation",
      "scenarioId": "chat-input-ready",
      "checkpointId": "input-ready",
      "operationRefs": ["send:enter-request", "send:submit"],
      "frame": { "mode": "region", "anchorHint": "对话输入区" },
      "captionPurpose": "说明输入需求和发送的入口"
    }
  ]
}
```

图片名称和显示编号由程序生成。计划只声明语义区域，像素坐标来自浏览器。为截图填写演示文本必须声明不会发送；若填写触发自动请求，仍执行现有网络守卫和风险规则。

## 6. 自动关联目标：确定性匹配与 AI 消歧结合

新增内部模块，集中负责关联功能、控件、页面状态和证据，避免每个调用方分别补定位配置。模块接收功能意图、观察结果和上下文，返回经验证的绑定或结构化缺口。

### 6.1 流程

1. 复用有效旧绑定或显式 targetHint，在正确的角色、状态和区域内验证。
2. 采集结构化观察：role、accessible name、label、test id、所属区域、可见性及状态线索。
3. 对稳定 ID 或名称精确匹配且唯一的目标，验证后绑定。唯一性必须在当前状态和作用域内成立。
4. 名称存在语义差异时，生成 Runtime 模型请求，让 AI 从有证据的候选中选择，并提交候选引用及理由。程序不自行猜测“上传附件”等同于哪个按钮。
5. 将候选编译为定位策略，重新定位并核对角色、名称、状态、可见性和唯一性。
6. 缺少候选时，根据明确的图文计划进入所需状态，再观察；不得无限点击探索。
7. 歧义、缺失、角色不符或状态断言失败时，保留原因，进入有界修复或等待流程。

不要把一次模型选择当作 verified。只观察到按钮可以证明入口存在；完整业务成功需要另有执行记录与结果断言。

### 6.2 观察范围需要扩展

现有候选机制主要发现按钮等控件。新流程还需识别 textbox、关联 label、命名区域、文件输入和拖放区域，以覆盖“在输入框写需求”“拖到输入区”等操作。区域缺少语义名称时，可以由 AI 提出源码支持的 selector 线索，再由浏览器验证；不得要求修改业务代码才能使用手册工具。

持久化只保留定位和审计所需字段。不要把包含真实用户内容的完整 DOM、文本摘要或带令牌的 URL 写入正式文档或可提交的模型请求。

### 6.3 状态与风险

展开菜单、切换标签等动作通过已有 Scenario setup 执行，每次进入状态后检查断言。发送消息、注册、上传、删除等沿用现有任务审批、写策略和 Demo/Fixture 规则。

为了展示生成内容，可以复用有效历史证据或使用已登记 Fixture。模拟数据须标明来源，不能声称真实生成成功。学校登录可展示入口和经授权的状态；外部授权、真实绑定过程不能为了截图自动提交。

## 7. 采集、裁剪与缓存

Figure 是读者视图，Capture 是证据；一个 Capture 可以派生多张 Figure，同一小节也可引用多个 Capture。按角色、环境、状态及数据修订组织采集，不能跨状态拼图。

优先扩展现有模块：

- `scenarios/*` 与 Runtime：执行状态计划、复用会话及检查点。
- `evidence/capture-page.js`：消费已验证绑定，记录控件几何及状态证据。
- `evidence/image-pipeline.js`：支持区域派生及局部标注。
- `annotations/proof.js`：记录图片、动作、标注和绑定的可验证关系。

裁剪必须进入统一几何管线：处理 CSS 像素、DPR、滚动和 fixed 元素，先满足现有隐私门禁并生成安全底图，再裁剪、换算标注位置和绘制。裁剪后的框、编号和关联目标必须仍在图内，隐私结果也要正确关联到最终产物。不能从未验证的 raw 图直接裁剪发布。

缓存分两层判断：

| 变化 | 处理 |
|---|---|
| 文案措辞或小节显示顺序 | 重建事实包和正文；稳定引用不变时复用图 |
| 标注集合、裁剪区域、主题、局部编号 | 有原图及所需有效几何时重新派生 |
| 新增目标但旧几何没有记录 | 补充浏览器定位和有效采集，不能猜坐标 |
| 控件绑定、状态步骤、角色、环境、Fixture 或来源变更 | 重新验证，按依赖补采受影响状态 |
| raw 被回收、状态断言失败、证据失效 | 明确报告并重新采集 |

计划、绑定、裁剪及渲染版本进入事实指纹和相关缓存键。绑定证据记入已有 Capture/Run 记录，语义模型和派生观察分开保存。不能通过在 capture 中隐式改写页面模型来制造新的事实来源。

## 8. 正文装配与发布检查

### 8.1 按小节装配

渲染顺序改为：标题与导语 → 页面入口 → 分类小节 → 小节内操作与相邻图片 → 必要结果说明 → 相关指南。

模型只补允许的说明文字，不得新增未登记操作、替换 UI 名称、修改图片引用或声称超出证据的完成结果。小节、图片、标注的对应由程序渲染并锁定到事实包中。

保留稳定的 manual block ID 和人工 owner 内容。迁移时不能删除 guide 块后直接重建整篇文档；需保存旧块到新块的映射，经已有三方合并处理，冲突产出可审阅提案。

### 8.2 文档级证据完整性

保留每张图的定位、绘制、隐私检查；增加跨 Figure 的文档检查。按正文实际收录的操作建立需求集合，再检查证据并集，不能只统计某一张图或 required 功能的分母。

正式发布要求：

1. 每项操作说明关联已登记的功能与操作。
2. 每项已收录操作具有符合 evidenceRequirement 的证据。
3. 入口标注证据要确认目标、区域、状态、最终图与标注均有效。
4. 说明展开后界面或结果时，对应状态图和断言有效，不能只拿入口图充数。
5. 正文中的图片/编号引用与最终产物一致，图片属于当前小节。
6. 控件存在、动作执行、结果验证、Fixture 模拟分开记录，不相互替代。
7. 概念或无图参考说明必须显式分类，有来源和无图理由，不能靠缺少 target 推导；修改分类会使相关检查失效并进入审阅。
8. 已收录操作未覆盖时，public 和 internal 的正式发布都阻断；草稿允许输出，但报告完整缺口。

保留 public 对未决 DOM 候选的现有规则；internal 可继续将未收录的候选作为警告。不能把页面上所有历史记录、按钮都变成必写功能。范围审核与正文完整性是两种检查。

报告分别给出：功能范围审核状态、已收录操作覆盖数量、图片绘制有效性、动作执行与结果验证范围。不再让单独的 `ok: true` 被误读为手册完整；零分母显示 N/A。

## 9. NeoAgent 的目标图文结构

### 9.1 AI 对话

| 小节 | 内容 | 图片计划 |
|---|---|---|
| 开始对话 | 新对话、输入需求、发送；停止生成作为后续状态 | 新对话入口图、可发送状态的输入区图；生成中状态有证据时单独展示 |
| 使用教学能力 | 示例、选择技能、移除技能、使用组合技 | 示例区域、展开的技能菜单、组合技菜单、已选标签，按状态分图 |
| 添加参考资料 | 上传、拖拽、云盘及活动结果引用 | 附件与云盘入口、文件选择界面、拖放提示；需要时补活动结果选择图 |
| 管理历史对话 | 查看全部、搜索、重命名、删除提示 | 历史区域、搜索界面、行操作菜单和删除确认提示；不执行删除 |
| 查看生成结果 | 产物卡片、查看完整内容 | 有产物的会话局部、打开后的预览；关联已有编辑/导出任务指南 |

## 11. 分阶段实施

### 阶段 A：确定契约与回归样本

- 明确 Feature/Operation/Section/Figure/Binding/EvidenceLink 的字段归属、版本与引用关系。
- 以登录缺第七项、AI 对话十项只画三项为可复现回归样本。
- 确定已收录操作的证据规则、局部编号及块迁移方案。
- 增补现有测试，先验证缺口不再被 optional 掩盖。

完成标准：模型能够表达类别、多状态图、概念说明和未解析操作；校验能识别遗漏与错误关联。暂不替换既有文档。

### 阶段 B：图文计划与目标关联

- AI 提交类别与图文计划，程序检查功能归属、状态引用和范围覆盖。
- 扩展观察并建立有界匹配/消歧/验证流程，复用已有 Runtime 等待机制。
- 记录绑定来源及修订；确保重名目标不能静默选中。
- `generate --plan` 输出小节、图片、状态、风险和待补证据。

完成标准：学校账号按钮、发送按钮、文件附件入口能从有效观察建立绑定；缺失或多匹配明确失败；计划不会执行新写操作。

### 阶段 C：分类图片与正文装配

- 使用既有 Scenario 和多变体采集，为 Figure 获取证据。
- 增加安全区域裁剪和局部标注，确保 DPR、遮罩与坐标一致。
- 按小节渲染图片、操作及图注，显示编号由 Figure 内顺序派生。
- 更新事实保护、合并、缓存、引用保留和网站展示。

完成标准：同状态可派生不同类别的局部图；不同状态有独立证据；移动小节不破坏身份；正文无悬空编号。

### 阶段 D：发布门禁与迁移

- 对正式正文建立操作需求集合，跨图片重算覆盖。
- public/internal 正式发布均拒绝已收录操作缺证据，草稿保留缺口报告。
- 提供显式迁移的预览与应用能力；先完成下述旧模型转换，再经 Runtime 补证据。
- 保持旧发布可读取；旧证据不自动升级验证等级，下一次正式发布需满足新规则。
- 更新相关架构、覆盖、迁移、Runtime 和 Skill 文档，并同步安装版本后再用于 NeoAgent。

完成标准：所有回归测试通过；迁移幂等、有备份/快照、可回退且保护人工块；不靠降低门禁让新发布通过。

### 阶段 E：NeoAgent 验收

- 先预览登录、AI 对话两篇的迁移和图文计划，再在已授权范围内补采。
- 分类生成两篇手册，逐张检查图与相邻说明。
- 检查项目内帮助中心的目录、锚点、图片、放大和响应式可读性。
- 验证两篇通过后，再按影响范围迁移其它页面；不直接全量重采所有手册。

## 12. 旧数据迁移策略

1. 保留现有 featureId、guideId、taskId、Scenario 与已发布块的身份。
2. 从旧 guide/detectedActions 提取候选操作和类别，由 AI 提交迁移语义输入；程序做引用和唯一性校验。
3. 没有 target 的条目先标 unresolved；纯概念说明经过显式分类后可无图。已有 optional 不直接作为免证据依据。
4. 旧 target 迁为 hint，复用既有有效证明后才成为 verified binding。
5. 旧图是否可复用按状态、来源、隐私、原图和几何完整性判断。需要新状态或新坐标就补采；不能在旧图上猜位置。
6. 将旧 guide 块映射到小节内容，人工块继续交由三方合并。仅计划重排且有冲突时输出 proposed，不强制覆盖。
7. 迁移预览列出新增小节/图、需补证据、可复用证据、风险动作及冲突。迁移执行保存快照，并检查重复执行无重复 ID。
8. 明确 schema 的兼容读取与版本策略；无法无损读取的新结构须配套迁移。不要仅添加可选字段却在读取时默默改变旧数据语义。

旧手册保留可读，不据此宣称符合新规则。迁移或发布失败时保留当前正式文档和图片，通过已有 publication 事务避免半篇更新。

## 13. 验证与验收标准

实施时增补有行为意义的测试，复用现有 annotation、variant、fact-pack、publication、cache 和 browser 测试体系。

| 测试场景 | 必须验证的行为 |
|---|---|
| 文案写学校登录，但缺少定位 hint | 从有效候选关联并验证，或明确缺口；不能静默跳过后正式发布 |
| AI 对话有十项，七项缺 target | 所有已收录操作有需求记录；没有证据时正式发布失败 |
| 重名、状态不同或角色不符的按钮 | 不误绑定；错误报告包含候选/状态原因且不泄漏敏感内容 |
| 展开组合技或云盘菜单 | 状态断言通过后才采集；入口图不能代替展开状态图 |
| 同页不同类别 | 图与说明相邻；默认不重复整页图承载不同类别 |
| 单图标注超限 | 按小节和状态拆分，满足上限及稳定引用 |
| 局部图在不同 DPR/滚动状态下派生 | 遮罩、框、编号正确；越界或遮挡失败被检查发现 |
| 小节重排、编号变化 | 稳定 ID 不变；正文与最终图编号一致，无多余采集 |
| 修改图文或绑定计划 | 相关指纹失效，补采/派生范围正确；旧证明不能冒充新证明 |
| Fixture、入口观察、真实执行 | 验证等级与来源不同，模型不能润色成“已完成” |
| 迁移有人工作文案的旧文档 | 保留人工块，冲突可审阅，失败不损坏当前发布 |
| 正式页面与帮助中心 | 图片链接、锚点、目录、图注、放大以及窄屏展示可用 |

验收不以“所有按钮都标出来”为标准，也不预设十项介绍必须恰好十张图。最终要求：

- 已收录的操作说明按证据需求全部覆盖，无法覆盖时明确阻断正式发布。
- 每张图属于明确小节和真实状态，标注与说明对应，读者不必在大图和十项介绍之间反复找位置。
- 菜单、拖拽、产物等状态有合适的独立证据；图数量由操作与状态决定。
- target/绑定解析是工具内部过程，日常使用无需手工修补 YAML。
- 保持真实截图、隐私、写操作授权、事实保护和人工编辑保护的现有约束。
