## 方法与边界

选取提交型 `use-skill`、只读筛选型 `review-credits`、生成型 `generate-practice`。以任务模型、证据清单、正式 Markdown 和发布图逐项检查入口、前提、步骤、完成判断、异常处理、截图。生成耗时为本机 `/usr/bin/time -p` 的墙钟时间；人工修改量分别记录任务模型和正式文档的补充。`verify --artifacts` 只核对发布产物，不能证明当前线上业务可用。

首次阅读者是否能独立完成任务需要未参与编写的人实测；本轮没有此人的操作记录，因此该指标保持**待测**，不以自动回放代替。

## 后续优化记录

- 登录恢复：等待原因是 `auth-expired`、`auth-missing` 或 `login-required` 时，提示改为一次执行 `manual auth login --resume <Run ID>`。命令先检查 Run 与认证档案匹配，再打开交互登录；状态写入用户级私有缓存、关闭登录窗口后才继续原 Run。用模拟登录与 Run 测试验证调用顺序及输出不含 Cookie、会话参数；本轮没有新的真人登录，因此线上恢复速度尚未实测。
- 产物体积：NeoAgent 只读 `gc` 计划当前可回收对象为 0；42 个发布记录、38 个 Capture 是保留根。现有发布记录约 860 KB、快照约 20 MB、发布图约 17 MB。历史保留策略尚未改变，不能把只读盘点报告成已清理。
- 重复发布：发布器现在核对文档、事实、Capture、定义版本、源码基线、生成正文和发布图；全部相同且文件完整时直接复用当前发布记录。NeoAgent 的 `review-credits` 用安装版重复定稿，发布记录数保持 9，当前 release ID 不变；随后 `verify --artifacts` 通过。此优化防止后续重复生成继续堆积相同记录，尚未删除历史记录。
- 读者核对项：`completion.readerChecks` 进入任务事实包并由完成段稳定渲染，仍与绑定断言的已验证结果分开。`generate-practice` 的题目预览、内容和数量核对已从块外人工段落移入任务模型；安装版重新定稿并通过产物校验。此项是读者检查说明，不证明题目内容已经符合需求。
