# 使用手册生成流程优化计划

目标：在已有项目中，从指定任务到可审阅手册尽量只需一条 `generate` 命令；登录过期时保留 Run，登录后继续；缓存命中时不启动浏览器。以 NeoAgent 测试环境作为实践样本。

## 验收口径

- 记录规划时间、实际耗时、浏览器场景数、等待输入次数和最终文档路径；区分缓存命中与重新采集，不用一次运行推断普遍提速。
- 认证失效在采集和测试数据准备前暴露，给出 `auth login` 与 `resume` 命令；登录后已成功节点不重做。
- 已有有效证据的文案生成无需登录；多目标共用 Run 和浏览器会话。
- 生成文档需逐项核对目标、前提、步骤、完成标志、异常处理和截图对应关系；快速默认文案只能作为草稿。

## NeoAgent 文档抽查

- `tasks/use-skill.md` 第 6 步动作句与说明都要求点击「发送」。确定性渲染现在删除说明中与动作句完全相同的开头，仅保留新增的结果说明。正文中的教学主题示例仍应在交付时说明可替换。
- `tasks/review-credits.md` 标题包含查看消耗明细，完成声明却只验证积分中心打开；这是任务模型 `completion.claims` 绑定在 `open-credit-center` 的问题。需补充筛选结果的真实断言和证据，再按审批范围更新模型，不能由渲染器臆造成功。
- `chat.md` 是页面总览，包含三个入口的短说明，不足以独立完成教学任务。交付时应将任务型指南作为主要入口，并核对页面总览链接。

本轮未把以上抽查当作线上验证；图片、按钮状态和业务完成情况仍以真实采集与相应断言为准。
